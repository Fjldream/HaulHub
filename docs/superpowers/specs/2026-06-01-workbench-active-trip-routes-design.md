# 工作台进行中工单路线设计

## 背景

工作台当前有“进行中趟次监控”区域，但它仍是静态占位地图，文案也容易让用户以为系统已经接入车辆实时定位。实际情况是车辆实时定位暂未接入，但趟次工单已经保存装货地、卸货地以及可选经纬度。第一版应利用现有工单路线数据，让调度和会计能在工作台看到车队当前正在执行哪些运输区间。

本设计聚焦后台工作台，不改司机端任务流程，不新增实时定位、轨迹回放或 GPS 数据采集。

## 目标

- 在工作台展示进行中趟次的装卸货路线。
- 明确表达“路线来自工单地点，不代表车辆实时位置”。
- 帮助调度快速识别正在运输的车牌、司机、客户和路线。
- 对缺少经纬度的工单给出可处理入口，而不是画错误路线。
- 复用现有高德地图接入，控制前端包体和后端复杂度。

## 非目标

- 不展示车辆实时位置。
- 不保存车辆历史轨迹点。
- 不计算预计到达时间、偏航、超速或滞留。
- 不新增离线地图、地图瓦片缓存或大规模车辆聚合。
- 不重做工作台整体布局。

## 推荐方案

采用“路线态势图”方案：地图为主，路线列表为辅。

工作台模块改名为“进行中工单路线”。模块标题下显示说明：“按工单装卸货地点生成路线，当前未接入车辆实时定位。”地图展示可绘制路线，列表展示所有进行中趟次，并提示哪些路线缺少坐标。

此方案比列表优先方案更符合“在地图上看车队工单路线”的目标，也比准进度看板更能复用现有地点坐标能力。第一版不做复杂轨迹能力，能快速上线并为后续 GPS 接入留下清晰位置。

## 用户体验

### 默认视图

- 地图显示所有可绘制的进行中趟次。
- 每条路线包含装货点、卸货点和路线线条。
- 路线列表显示车牌、司机、客户、装货地、卸货地、开始时间和坐标状态。
- 如果存在缺坐标趟次，列表中显示“待补地点”状态，并提供编辑入口。

### 选中交互

- 点击列表中的路线后，地图聚焦到对应装卸货区间。
- 被选中的路线使用更高对比度线条，其他路线降低视觉权重。
- 点击地图路线或端点时，显示简短信息卡：车牌、司机、客户、装卸货地、创建时间、详情入口。
- “查看列表模式”跳转到趟次列表，并带上 `status=in_progress`。
- “全屏展开地图”第一版可以保留为后续能力，或打开一个更大的路线地图视图；若不实现，应移除不可用按钮，避免操作失败。

### 空态

- 没有进行中趟次时，地图区域显示空态：“暂无进行中工单路线”。
- 有进行中趟次但全部缺坐标时，不展示伪地图路线，显示“这些工单需要补充装卸货坐标后才能上图”。
- 高德地图加载失败时，展示路线列表和错误提示，用户仍能进入趟次详情。

## 文案原则

禁止使用会造成误解的文案：

- 实时位置
- 车辆监控
- 当前车辆所在地
- 轨迹追踪

推荐使用：

- 工单路线
- 装卸货路线
- 按工单地点生成
- 当前未接入车辆实时定位
- 路线仅表示计划运输区间

## 数据与状态

第一版复用 `/admin/trips` 返回的 `ApiTrip` 数据：

- `status`
- `tripNo`
- `customerName`
- `vehicle.plateNumber`
- `driver.name`
- `loadLocation`
- `loadAddress`
- `loadLatitude`
- `loadLongitude`
- `unloadLocation`
- `unloadAddress`
- `unloadLatitude`
- `unloadLongitude`
- `locationProvider`
- `createdAt`

数据库已有 `startedAt` 字段，但当前后台 API 类型未暴露它。第一版先使用 `createdAt` 展示工单创建时间；后续如果需要更准确表达“开始运输时间”，再把 `startedAt` 加入序列化和前端类型。

可绘制条件：

- `status === "in_progress"`
- 装货地和卸货地均有经纬度

缺坐标条件：

- 趟次处于进行中，但任一端缺少经纬度

路线优先级：

1. 第一版使用装卸货两点连线，保证稳定、快速和轻量。
2. 后续可接入高德驾车路线规划，将直线替换为道路路线。

## 组件设计

### 地图加载工具

从 `TripLocationPicker` 中抽出高德地图脚本加载逻辑，形成共享工具，例如：

- `loadAmap()`
- 高德 key 和安全码读取
- SDK 加载失败错误处理

这样地点选择器和工作台路线图共用同一份加载逻辑，避免重复脚本注入和配置分叉。

### WorkbenchTripRouteMap

新增客户端组件，职责是展示工作台路线地图。

输入：

- `trips: ApiTrip[]`

内部派生：

- `drawableRoutes`
- `missingCoordinateTrips`
- `selectedTripId`

职责：

- 加载高德地图。
- 绘制 marker 和路线线条。
- 管理选中高亮。
- 展示地图加载失败、空态和缺坐标提示。
- 将详情跳转交给 Next `Link` 或普通链接。

该组件不负责请求数据，不负责修改趟次，不负责实时刷新。

### 工作台页面

`apps/admin-web/src/app/page.tsx` 继续在服务端拉取趟次和报表数据。页面只把 `inProgressTrips` 传给客户端地图组件，并保留原有指标卡和财务概览。

为了减少不必要的数据量，后续可把工作台趟次请求调整为 `/admin/trips?status=in_progress&pageSize=50`，但第一版可以先复用已有请求。

## 错误处理

- 缺少 `NEXT_PUBLIC_AMAP_JS_KEY`：地图区域展示配置缺失提示，路线列表仍可用。
- 高德脚本加载失败：展示错误提示和重试入口，保留列表。
- 趟次缺坐标：进入“待补地点”状态，不绘制错误点位。
- 坐标异常或无法转换：跳过绘制该路线，并在列表中显示“坐标异常”。
- 进行中趟次过多：第一版最多展示最近 50 条，超过后提示“仅展示最近 50 条路线”。

## 性能与体积

地图 SDK 通过运行时脚本加载，不打进前端构建包。第一版新增的本地代码主要是一个客户端组件、共享地图加载工具和少量样式，部署包体增长应很小。

工作台打开时会额外加载高德地图脚本和地图瓦片，这会增加页面运行时网络请求，但不等于软件安装包或部署包显著变大。

## 测试策略

单元测试：

- 路线数据派生函数：完整坐标、缺装货坐标、缺卸货坐标、非进行中状态。
- 文案状态：无路线、全部缺坐标、部分缺坐标。

组件或页面验证：

- 工作台有进行中路线时显示地图和列表。
- 点击列表项后选中状态变化。
- 缺地图 key 时显示可理解错误，而不是白屏。
- 无进行中趟次时显示空态。

手动验证：

- 在本地工作台打开页面，确认高德地图非空白。
- 使用至少两条有坐标趟次验证路线和端点。
- 使用一条缺坐标趟次验证“待补地点”入口。
- 在移动宽度下确认列表、按钮和地图区域不重叠。

## 后续演进

- 新增全屏路线地图页。
