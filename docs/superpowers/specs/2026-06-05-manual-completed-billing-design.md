# 手工补录完成账单设计

## 背景

HaulHub 现有利润统计基于已完成趟次的 `SettlementSnapshot` 汇总。管理员现在需要补录系统外已经完成的运输账单，用于计算利润并进入现有车辆、司机、费用类型和利润报表。

第一版只处理“补录系统外已完成运输”。如果系统里已经有趟次但司机没有完成提交流程，仍走现有趟次审核和结算流程，不纳入本功能范围。

## 目标

- 管理员可以在后台一次性录入一张已完成账单。
- 补录账单保存后立即成为标准 `completed` 趟次。
- 补录账单进入现有利润统计，不新增独立利润口径。
- 费用支持逐条明细录入，也支持只填总费用。
- 车辆和司机必须来自现有档案，并校验司机已绑定所选车辆。
- 票据可以上传，但不强制。
- 利润报表按管理员填写的完成/结算日期归档。

## 不包含

- 不支持临时车辆或临时司机文本录入。
- 不支持补录时绕过现有团队、角色和车辆司机权限边界。
- 不把手工账单建成独立表。
- 不要求补录票据满足费用类型的必传票据规则。
- 不在第一版支持批量导入 Excel。

## 用户流程

1. 管理员进入后台趟次管理。
2. 点击“补录完成账单”。
3. 选择已有可用车辆。
4. 页面根据车辆过滤可用司机，只显示绑定到该车辆且在职的司机。
5. 填写客户、装货地、卸货地、实际运费、完成/结算日期和会计备注。
6. 选择费用录入模式：
   - 明细模式：逐条填写费用类型、金额、发生日期、备注，保存后可给费用补传票据。
   - 总费用模式：只填写一个总费用和备注。
7. 页面实时显示实际运费、费用合计、预计利润和利润率。
8. 管理员点击“保存并计入利润统计”。
9. 系统创建已完成趟次、费用、结算快照和审计日志。
10. 保存成功后跳转到新创建的趟次详情页。

## 页面设计

新增页面：`/trips/manual-completed/new`

入口：

- 在趟次列表的“创建趟次”旁新增“补录完成账单”按钮。
- 利润统计页可增加次要入口，方便会计从报表页补历史账。

页面分为四块。

### 车辆与司机

字段：

- 车辆，必填，只能选择可用车辆。
- 司机，必填，选择车辆后只显示绑定到该车辆且在职的司机。

提示：

- 如果车辆没有绑定可用司机，提示“该车辆暂无可用司机，请先在车辆或司机档案中绑定。”
- 如果提交时司机不属于所选车辆，提示“该司机未绑定所选车辆，请重新选择。”

### 运输信息

字段：

- 客户名称，必填。
- 装货地，必填。
- 卸货地，必填。
- 实际运费，必填，金额最多两位小数，允许 0。
- 完成/结算日期，必填，默认今天，允许选择历史日期。
- 会计备注，选填。

实际运费允许为 0，是为了支持特殊补录场景；此时利润率显示为不可计算。

### 费用录入

费用录入有两种互斥模式。

明细模式：

- 默认模式。
- 支持新增和删除费用行。
- 每行包含费用类型、金额、发生日期、备注和票据状态。
- 费用类型来自当前团队已启用的 `ExpenseType`。
- 金额最多两位小数，允许 0。
- 发生日期默认完成/结算日期，可修改。
- 票据不在创建表单中强制上传。保存成功进入趟次详情页后，管理员可以给每条费用补传票据。

总费用模式：

- 用于历史账单只有成本总数、没有费用明细的情况。
- 字段包含总费用金额和备注。
- 保存时系统创建一条费用记录，费用类型为“补录总费用”。
- 如果当前团队没有启用的“补录总费用”费用类型，后端自动创建一个不强制票据、启用、排序靠后的费用类型。

明细模式和总费用模式不能同时提交。如果用户切换模式，页面清楚展示当前模式，并只提交当前模式的数据。

### 保存前预览

页面右侧或底部显示实时摘要：

- 实际运费。
- 费用合计。
- 预计利润。
- 利润率。

费用大于运费时利润显示为负数，但允许保存。

保存按钮文案：`保存并计入利润统计`。

## 后端接口

新增接口：`POST /admin/trips/manual-completed`

请求体：

```ts
{
  vehicleId: string;
  driverId: string;
  customerName: string;
  loadLocation: string;
  unloadLocation: string;
  actualFreight: string;
  settledAt: string;
  accountingNote?: string;
  expenses?: Array<{
    expenseTypeId: string;
    amount: string;
    occurredAt?: string;
    note?: string;
  }>;
  totalExpense?: {
    amount: string;
    note?: string;
  };
}
```

规则：

- 只允许 `accountant` 角色调用。
- 请求受当前用户团队范围限制。
- `vehicleId` 必须属于当前团队且状态为可用。
- `driverId` 必须属于当前团队、角色为司机、状态为在职。
- 所选司机必须绑定到所选车辆。
- `actualFreight` 必须是最多两位小数的金额字符串，允许 0。
- `settledAt` 必须是有效日期。
- `expenses` 和 `totalExpense` 必须二选一，不能都传，也不能都不传。
- 明细模式下至少一条费用。
- 明细费用类型必须属于当前团队且启用。
- 费用金额必须是最多两位小数的金额字符串，允许 0。

所有写入使用数据库事务完成。

事务内创建：

1. `Trip`
   - `status = completed`
   - `estimatedFreight = actualFreight`
   - `actualFreight = actualFreight`
   - `completedAt = settledAt`
   - `createdBy = 当前管理员`
   - `submittedAt = null`
   - `reviewStartedAt = null`
   - `accountingNote = 请求值`
2. `Expense[]`
   - 明细模式逐条创建。
   - 总费用模式创建一条“补录总费用”费用。
   - `createdBy = 当前管理员`
   - `expenseTypeNameSnapshot` 使用保存当时的费用类型名称。
3. `SettlementSnapshot`
   - `actualFreight = actualFreight`
   - `expenseTotal = 所有费用金额之和`
   - `profit = actualFreight - expenseTotal`
   - `profitRate = profit / actualFreight`，实际运费为 0 时为空。
   - `settledBy = 当前管理员`
   - `settledAt = 请求中的 settledAt`
4. `AuditLog`
   - `targetType = Trip`
   - `targetId = 新建趟次 ID`
   - `action = trip.manual_completed_created`
   - `after` 记录车辆、司机、实际运费、费用合计、利润、完成/结算日期和费用模式。

接口返回：

```ts
{
  trip: ApiTrip
}
```

### 管理员票据上传

补录创建接口不接收票据文件，避免在同一个事务里混合账单落账和文件上传。创建成功后，趟次详情页为费用行提供可选上传入口。

新增接口：`POST /admin/expenses/:expenseId/receipt-images`

规则：

- 只允许 `accountant` 角色调用。
- 费用必须属于当前团队。
- 费用所属趟次不能是 `cancelled`。
- 已完成趟次也允许补传票据，因为补录账单通常是历史资料整理。
- 上传后创建 `ReceiptImage`，并在趟次详情页展示缩略图和预览。

新增接口：`POST /admin/receipt-images/:receiptImageId/delete`

规则：

- 只允许 `accountant` 角色调用。
- 票据必须属于当前团队。
- 票据所属趟次不能是 `cancelled`。
- 删除只移除 `ReceiptImage` 记录；文件清理可沿用现有上传目录清理策略，或作为后续维护任务处理。

## 数据模型影响

本功能不新增数据库表。

现有 `SettlementSnapshot.settledAt` 已有默认值 `now()`。为支持历史补录，接口创建结算快照时必须显式传入 `settledAt`。

手工补录账单通过 `Trip.status = completed` 与普通完成趟次共用列表和报表。第一版不新增 `manual` 字段；是否手工补录可通过审计日志识别。后续如果需要在列表中筛选“手工补录”，可再增加 `Trip.source` 或 `Trip.isManual` 字段。

## 报表规则

利润统计继续只读取 `SettlementSnapshot`。

补录账单进入：

- 趟次总数。
- 实际运费合计。
- 趟次费用合计。
- 利润合计。
- 车辆利润统计。
- 司机利润统计。
- 费用类型统计。
- 周、月、年趋势。

归档日期使用 `SettlementSnapshot.settledAt`，也就是管理员填写的完成/结算日期。

## 错误提示

前端和后端都需要给出明确提示：

- 未选择车辆：`请选择车辆。`
- 未选择司机：`请选择司机。`
- 车辆不可用：`车辆不可用，不能补录完成账单。`
- 司机不可用：`司机不可用，不能补录完成账单。`
- 司机未绑定车辆：`该司机未绑定所选车辆，请重新选择。`
- 客户名称为空：`请填写客户名称。`
- 装货地为空：`请填写装货地。`
- 卸货地为空：`请填写卸货地。`
- 实际运费格式错误：`实际运费请输入最多两位小数的数字。`
- 完成日期为空：`请选择完成/结算日期。`
- 金额格式错误：`金额请输入最多两位小数的数字。`
- 费用类型停用：`该费用类型已停用，请重新选择。`
- 同时提交明细和总费用：`费用明细和总费用只能选择一种录入方式。`
- 没有提交费用：`请录入费用明细，或切换为只填总费用。`
- 保存失败：`补录账单保存失败，请检查信息后重试。`

## 测试计划

后端测试：

- 成功补录明细费用后返回已完成趟次。
- 成功补录明细费用后创建 `SettlementSnapshot`。
- 成功补录总费用后使用或创建“补录总费用”费用类型。
- 补录创建接口不要求票据。
- 管理员可在补录完成后的费用上上传票据。
- 利润和利润率计算正确。
- 实际运费为 0 时利润率为空。
- `settledAt` 使用请求传入日期。
- 利润报表按 `settledAt` 归档补录账单。
- 车辆不存在或不可用时报错。
- 司机不存在或停用时报错。
- 司机未绑定车辆时报错。
- 同时传费用明细和总费用时报错。
- 两种费用都没传时报错。
- 金额格式错误时报错。
- 费用类型停用或不属于当前团队时报错。
- 事务失败时不留下半成品趟次、费用或结算快照。

前端测试：

- 车辆选择后司机选项按绑定关系过滤。
- 没有可选司机时展示绑定提示。
- 明细模式和总费用模式切换时只提交当前模式。
- 实时摘要正确计算费用合计、利润和利润率。
- 实际运费为 0 时利润率显示不可计算。
- 必填项错误提示显示清楚。
- 保存成功后跳转到新创建的趟次详情页。
- 趟次详情页允许管理员给已完成费用补传可选票据。

## 后续扩展

- 批量导入历史账单。
- 在趟次列表增加“手工补录”筛选。
- 增加 `Trip.source` 字段区分司机流程、后台补录、批量导入。
- 允许补录时上传回单、合同等非费用票据。
- 支持对已完成补录账单发起更正流程，保留原结算快照和更正日志。
