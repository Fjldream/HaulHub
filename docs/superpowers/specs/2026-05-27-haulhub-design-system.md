# HaulHub Design System 设计规范

## 设计定位

HaulHub 是面向小型货车运输公司的内部经营工具，不是营销展示型产品。系统同时服务两个高频场景：司机在手机上快速记账和提交趟次账单，会计在电脑上高效核对、筛选、审核、结算和统计利润。

整体气质：清晰、可信、克制、高效率、有财务安全感。

设计关键词：物流运营、账单准确、状态清楚、后台高密度、移动端易操作、财务边界明确。

Stitch UI 已确立的视觉方向作为新版主基准：深海军蓝代表稳定与可信，安全橙代表待处理和行动提醒，浅灰蓝背景承载长期办公场景，白色容器承载核心数据。

## 核心原则

### 1. 先完成任务，再追求装饰

所有页面优先服务当前任务，例如司机记录费用、会计审核账单、查看利润统计。视觉层级必须帮助用户快速判断下一步动作。

禁止把后台做成宣传页、仪表盘大海报或装饰性卡片墙。卡片只用于独立信息块、移动端趟次、弹窗和摘要，不用于包裹整段页面。

### 2. 金额、状态、责任对象必须醒目

车牌号、司机、客户、趟次状态、费用合计、实际运费、利润、票据缺失和退回原因是核心信息。它们在列表、详情和审核流中必须稳定出现。

金额必须使用等宽数字，保留两位小数。关键金额不能使用低对比灰色，利润正负必须同时通过颜色和符号表达。

### 3. 司机端少填、后台端可查

司机端表单字段要少、控件要大、流程要短。后台端允许更高信息密度、更多筛选和批量操作。

司机端不要照搬后台筛选项，不要要求司机填写会计才需要的信息。

### 4. 隐私边界是设计红线

司机端永远不展示预计运费、实际运费、利润、利润率、经营报表和其他司机数据。这个规则适用于页面、通知、错误提示、空状态和接口返回后的前端渲染。

### 5. 状态变化必须可感知

趟次状态、审核锁定、退回原因、必传票据缺失、提交成功和上传失败都必须有明确反馈。状态不能只依赖颜色，必须配合文字、图标或解释。

## 色彩系统

### 品牌主色

新版主色采用 Stitch UI 的深海军蓝。

- Brand 900: `#001B3C`
- Brand 800: `#002045`
- Brand 700: `#1A365D`
- Brand 600: `#2D476F`
- Brand 100: `#D6E3FF`
- Brand 50: `#F0F3FF`

适用：顶部栏、侧边栏、主按钮、当前导航、关键链接、后台高优先级操作。

不要：大面积铺满页面背景、表达危险操作、让所有图表都变成同一种蓝。

### 行动强调色

安全橙用于行动提醒、待处理、重要次级动作和部分警示。

- Accent 500: `#F6AD55`
- Accent 400: `#FFB55C`
- Accent 100: `#FFDDBA`

适用：待审核、待确认、票据缺失、需要会计处理的事项、司机端“新增费用”等高频行动入口。

不要：表达成功、删除或长期大面积铺底。

## 字体系统

### 字体栈

标题优先使用 Hanken Grotesk，正文和数据优先使用 Inter。中文环境必须有系统中文字体回退。

```css
--font-heading: "Hanken Grotesk", Inter, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", Arial,
  sans-serif;

--font-body: Inter, -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", Arial, sans-serif;

--font-mono-number: Inter, "SFMono-Regular", Consolas, "Liberation Mono",
  monospace;
```

金额和统计数字必须启用：

```css
font-variant-numeric: tabular-nums;
```

### 字号

后台端：

- 页面标题：24px / 32px，600
- 区块标题：18px / 26px，600
- 表格正文：14px / 22px，400
- 辅助说明：13px / 20px，400
- 表格小字：12px / 18px，400

司机端：

- 页面标题：20px / 28px，600
- 卡片标题：17px / 24px，600
- 正文：15px / 23px，400
- 表单标签：14px / 22px，500
- 辅助说明：13px / 20px，400

不要使用负字距。不要用 12px 以下文字承载司机端关键内容。

## 间距与布局

使用 4px 基准单位。

- 4px：极小间距
- 8px：紧凑内部间距
- 12px：字段和小组件间距
- 16px：常规内边距
- 24px：页面模块间距
- 32px：大模块间距
- 40px：桌面页面边距

后台采用左侧导航 + 顶部用户区 + 内容工作区。核心表单建议控制在 960px 内，核心表格可横向占满工作区。

司机端采用单列布局，左右边距 16px。底部关键操作固定在安全区域上方，主要触控目标不小于 44px，高频操作建议 48px。

## 圆角、边框、阴影

圆角保持克制：

- 2px：极小标签、细粒度控件
- 4px：默认按钮、输入框、表格筛选、Stitch 基准控件
- 6px：紧凑卡片、选择器
- 8px：大卡片、弹窗、后台摘要容器
- 9999px：状态标签和头像

边框：

- 默认边框：`#E2E8F0`
- 强调边框：`#C4C6CF`
- 聚焦边框：`#1A365D`
- 错误边框：`#BA1A1A`

阴影尽量少用，以边框和背景层级为主：

- Card: `0 1px 2px rgba(26, 54, 93, 0.06)`
- Popover: `0 8px 20px rgba(26, 54, 93, 0.10)`
- Modal: `0 12px 32px rgba(26, 54, 93, 0.16)`

不要卡片套卡片，不要彩色阴影，不要依赖重阴影制造层级。

## 核心组件规范

### 按钮

按钮类型：

- Primary：页面唯一主操作，深海军蓝背景，白字。
- Accent：高频行动或待处理入口，安全橙背景，深色文字。
- Secondary：返回、取消、辅助动作，白底边框。
- Danger：删除、退回、停用，危险色。
- Text/Icon：低风险或紧凑操作。

一个区域只保留一个主按钮。删除不能做成主色按钮。危险确认必须写清楚对象，例如“退回账单”“停用司机”。

### 输入框

后台输入高度 36px，司机端输入高度 44px。标签始终显示在输入框上方，不只依赖 placeholder。错误信息放在字段下方，并说明修正方式。

金额输入必须显示单位“元”，提交时校验大于 0，展示时保留两位小数。

### 状态标签

状态标签使用浅底深字，配合文字，不只依赖颜色。

- 待出车：灰色
- 进行中：信息蓝
- 已提交：安全橙
- 审核中：安全橙
- 已完成：成功绿
- 已退回：危险红

同一状态在全系统使用同一名称、颜色和行为。

### 表格

后台核心列表使用表格，不用卡片替代表格管理大量数据。表头清晰，金额右对齐，状态靠左或居中，操作列固定在右侧。超过 10 行时可使用轻微斑马纹或 hover 辅助横向扫描。

适用：趟次管理、车辆管理、司机管理、费用类别配置、利润统计、结算中心。

### 卡片

卡片用于移动端趟次、费用记录、统计摘要和独立信息块。白底、细边框、16px 内边距、8px 圆角。司机端每张趟次卡片右上角必须显示状态标签。

不要把后台长表格拆成大量卡片，不要卡片套卡片。

### 上传组件

票据上传支持拍照和相册选择，显示缩略图、上传进度、重试和删除入口。审核场景必须能打开清晰大图。必传票据缺失时必须明确指出缺少哪类票据。

### 弹窗与抽屉

后台短表单可用弹窗，详情查看和审核可用右侧抽屉或详情页。司机端优先使用全屏页面或底部面板，不使用小型居中弹窗承载复杂表单。

### 导航

后台使用左侧导航，核心模块包括工作台、趟次管理、结算中心、车辆管理、司机管理、费用类别配置、利润统计、系统设置。

司机端使用底部导航或简单顶部返回，核心模块包括我的趟次、新增费用入口、个人中心。司机端不要出现复杂多级菜单。

## 状态与反馈

加载：列表使用骨架屏或轻量 loading，按钮提交中禁用并显示明确文案。

空状态：说明当前没有什么，以及下一步能做什么。不要只写“暂无数据”。

错误：说明问题和解决方式。不要直接暴露技术错误码。

禁用：关键禁用状态必须有原因，例如“缺少必传票据，暂不能提交账单”。

成功：短而明确，必要时提供后续动作。不要每个小操作都弹强提示。

## 文案语气

文案直接、清楚、可信，像一个可靠的内部系统。少用营销语，多用动作和结果。

按钮推荐使用动词加对象：

- 开始出车
- 新增费用
- 提交账单
- 开始审核
- 完成结算
- 退回修改

错误文案示例：

- 请上传该费用类型要求的票据照片。
- 金额必须大于 0。
- 该车辆正在维修中，不能创建新趟次。

财务文案必须准确，不用主观词替代数字。草稿利润必须标注为“待确认利润”。

## 信息安全与财务红线

### 司机端隐私红线

司机端绝不展示：

- 预计运费
- 实际运费
- 利润
- 利润率
- 经营报表
- 其他司机的趟次

禁止通过展开、详情、通知、错误提示或接口残留信息泄露这些数据。

### 财务准确红线

金额必须清晰、统一、可核对。存储使用 decimal，不使用浮点数。所有金额展示保留两位小数。

计算规则：

```text
费用合计 = 所有费用金额之和
利润 = 实际运费 - 费用合计
利润率 = 利润 / 实际运费
```

实际运费为空或 0 时，利润率显示为不可计算。

### 后台效率红线

后台管理页优先表格、筛选、批量扫描和审核效率。不要为了美观牺牲表格密度，不要让会计为了核对一趟账单反复跳页面。

## 页面基准

### 司机端

司机端应像一个随手记账工具：

- 首页直接看到自己的趟次
- 趟次卡片清楚显示车牌、客户、路线和状态
- 新增费用不超过一个屏幕的核心字段
- 上传票据入口明显
- 提交账单前清楚列出费用合计和缺失项

司机端不做后台缩小版，不展示复杂报表。

### 会计后台

会计后台应像一个账单审核和利润核算工作台：

- 左侧导航稳定
- 顶部筛选清楚
- 列表可快速扫描
- 详情页能完成审核闭环
- 利润统计能按车辆、司机、时间和趟次状态筛选

## 设计验收清单

每个新页面或新功能上线前检查：

- 是否符合司机端和后台端的使用场景差异
- 是否保护司机端运费和利润隐私
- 是否使用统一状态名称、颜色和标签
- 是否有清楚的加载、空、错误、禁用和成功状态
- 金额是否使用统一格式和等宽数字
- 主操作是否唯一且明显
- 手机端触控目标是否足够大
- 后台列表是否支持快速筛选和扫描
- 是否避免卡片套卡片、过度装饰和营销式布局

## 落地资产

前端实现应优先消费 [design/tokens.json](../../../design/tokens.json)。文档负责原则和用法，tokens 负责可执行的颜色、字号、间距、圆角、阴影、状态和组件基础值。
